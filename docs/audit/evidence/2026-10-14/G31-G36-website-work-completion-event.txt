G-31 / G-36: dead WebsiteWorkService.CompleteAsync removed; approval now publishes websiteWorkCompleted
Date: 2026-10-14
Branch: fix/remove-dead-website-work-complete, base main after #80

G-31 (RISK P3, from Phase 4): WebsiteWorkService.CompleteAsync set a task to Done without manager
  review. No route called it: POST /api/me/website-work/{id}/complete maps to
  WebsiteWorkReviewService.SubmitAsync (WebsiteWorkController.cs:182-184). Only unit tests used it.

G-36 (VERIFIED BUG P3, found while removing it): CompleteAsync was also the only caller of
  IWebsiteWorkRealtimePublisher.PublishCompletionAsync. The real completion path,
  WebsiteWorkReviewService.ApproveAsync, wrote the website-work.completed activity but never sent the
  "websiteWorkCompleted" hub event. So the Admin Web handlers for it never fired in production:
    - WebsiteWorkRealtimeNotice.tsx "Work completed" toast
    - WebsiteWorkManagement.tsx:210-220 live "recent completions" list and refresh
  Other managers' Website Work pages only caught up on reload (progress polls every 5 s, but the
  completions list does not).

Change:
  - WebsiteWorkReviewService.ApproveAsync publishes the completion after SaveChanges, wrapped like the
    existing submission publish (failure is logged; the approval stays saved).
  - WebsiteWorkService.CompleteAsync and its interface entry removed; the now-unused publisher and
    logger constructor parameters removed (TreatWarningsAsErrors would flag them).
  - Tests: WebsiteWorkServiceTests completes through submit + approve; the regression test checks a
    second employee cannot submit the first employee's work (NotFound); WebsiteWorkReviewServiceTests
    asserts approval publishes exactly one completion for the right task and employee.
