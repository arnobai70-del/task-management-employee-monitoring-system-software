G-08: presence and task-status labels state what is measured
Date: 2026-10-14
Branch: fix/presence-status-labels, base main after #81

Finding (RISK P1, Phase 1): the Admin Web called an employee "Working" when the server only knows
that the desktop agent's heartbeat is fresh and an attendance session is open
(RealtimeWorkspaceService.cs:241: Offline / OnBreak / Working / Idle). "Idle" likewise implied an
activity judgement the system does not make. Website-work task status InProgress was also shown as
"Working". DESIGN_SYSTEM.md §5 requires labels that state what is measured and never imply productivity.

Change (display only; API values unchanged for other clients):
  Presence (PresencePanel.tsx):  Working -> "On shift", OnBreak -> "On break",
                                 Idle -> "Connected, not on shift", Online -> "Connected"
                                 summary "N online · N working" -> "N connected · N on shift"
  Task status InProgress -> "In progress" (PresencePanel, WebsiteWorkManagement, ProductivityReports,
                                 WebsiteWorkFollowUps); live board "Working now / Working for" ->
                                 "In progress now / In progress for" with "Targets started and not yet submitted".
  Not changed: ProductivityReports "Working time", which the page already defines as start/reopen to
  submission.

Check: Vite dev server, Playwright + Chromium, every /api call mocked; presence list has four fictional
employees (one per server state); fictional token with reports.read + presence.read.
