G-56 — Every monitoring write endpoint answered 500
Date: 2026-10-14 (UTC). Control: main ba7708d. Fix: branch fix/g56-monitoring-validation.
Found while measuring desktop traffic for G-09. Data: fictional only (local PostgreSQL 16).

Cause
src/Backend/TaskMonitoring.Api/Contracts/MonitoringContracts.cs (since 87e5fb5, 2026-09-30) declared the
validation attributes of five request records as [property: Range/Required/StringLength] on positional
record parameters. ASP.NET Core MVC refuses that at model validation and throws before the action runs:
  System.InvalidOperationException: Record type 'TaskMonitoring.Api.Contracts.UpdateMonitoringPolicyRequest' has validation metadata defined on property 'DisclosureText' that will be ignored. 'DisclosureText' is a parameter in the record primary constructor and validation metadata must be associated with the constructor parameter.
No other contract file uses [property: ...]. No HTTP test covered the monitoring endpoints, so it went unnoticed.

== Reproduction on main (local API, Development, curl) ==
PUT  /api/monitoring/policy                       -> 500
POST /api/monitoring/applications                 -> 500
POST /api/monitoring/domains                      -> 500
POST /api/me/monitoring/application-activity      -> 500   (employee token)
POST /api/me/monitoring/business-domain-activity  -> 500   (employee token)
GET  /api/monitoring/policy, GET /api/me/monitoring/policy -> 200 (reads were fine)
Effect: admins could not change the policy or add approved apps/domains (Admin Web Monitoring page save
fails), and the Employee Desktop could never record activity; it only shows "Approved activity sync delayed".
