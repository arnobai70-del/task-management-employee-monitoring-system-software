## 2. Prerequisites (names only — never commit values)
Env file `deploy/production/production.env` (from `production.env.example`): `APP_SITE_ADDRESS`, `UPDATE_SITE_ADDRESS`, `ACME_EMAIL`, `APP_PUBLIC_URL`, `UPDATE_PUBLIC_URL`, `PRODUCTION_HTTP_BIND/PORT`, `PRODUCTION_HTTPS_BIND/PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `JWT_ISSUER`, `JWT_AUDIENCE`, `POSTGRES_PASSWORD_SECRET_FILE`, `DATABASE_CONNECTION_SECRET_FILE`, `JWT_SIGNING_KEY_SECRET_FILE`, `AGENT_UPDATE_ENROLLMENT_KEY_SECRET_FILE`, `UPDATE_HOST_ROOT`, `BACKUP_ROOT`, `BACKEND_NETWORK_CIDR` (optional).
Secret files are generated by `scripts/production/init-production-secrets.sh` under `deploy/production/secrets/` (git-ignored).
Windows signing (GitHub Actions secrets, see `docs/windows-production-deployment.md`): signing certificate + password + publisher fingerprint — names to be confirmed with the owner.

## 3. Deploy (guarded path)
1. Confirm backup is fresh: `bash scripts/production/backup-postgres.sh <env> pre-deploy` → record the printed path.
2. `bash scripts/production/deploy.sh <env>` — builds images, runs the one-shot `--migrate-only` container (API has `Database__AutoMigrate=false`), then starts API/web/Caddy.
3. First install only: `bash scripts/production/bootstrap-admin.sh --env <env> --email <admin>` (one-shot).
4. Publish Windows release (signed bundle only): `bash scripts/production/publish-windows-release.sh --env <env> --bundle <dir>` (ZIP first, `release.json` last, immutable versions).

## 4. Smoke checks
- `curl -f https://<APP>/health/live` and `/health/ready` → 200.
- Admin login with a non-production test account, open Dashboard, Attendance, Website Work.
- `bash scripts/production/acceptance-server.sh --env <env> --channel stable`.
- One Employee Desktop sign-in and heartbeat visible in Presence.

## 5. Rollback
- Application: redeploy previous image tag/commit via `deploy.sh` with the previous checkout.
- Database: `bash scripts/production/restore-postgres.sh --env <env> --backup <path> --confirm-restore` (destructive — operator confirmation required; CI proves the restore path on synthetic data).
- Windows agents: previous version stays in the immutable archive; follow `scripts/windows/rollback-employee-windows.ps1` / central update controls.
