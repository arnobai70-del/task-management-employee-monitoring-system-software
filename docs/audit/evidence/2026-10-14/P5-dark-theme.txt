P5 Admin Web dark theme and colour contrast (G-37)
Date: 2026-10-14 (UTC). Base: origin/main d5b0ff4 (after #82). Branch: feat/admin-web-dark-theme.
Data: local API (docker, scratch database) seeded with fictional records only; bootstrap
admin audit-admin@example.invalid. Credentials were passed by environment variable and are not
in this file or in the script. Nothing was deployed.

Tool: scripts/audit/theme-contrast.mjs (Playwright Chromium 1366x900, axe-core 4.10.2 rule
color-contrast, WCAG AA 4.5:1). Visits /login and all 18 admin routes for each colour scheme.

What was wrong
1. No dark theme existed (master plan Phase 5, DESIGN_SYSTEM.md "tokens/dark theme").
2. Pre-existing contrast failures on main, light scheme (35 nodes on 18 of 19 pages):
   - Quick jump "Ctrl K" kbd: #8391a7 on #2b3445 = 3.91:1, every signed-in page
     (src/AdminWeb/src/admin-experience.css:504 before the fix).
   - Status badges inside panel headings took the muted heading colour instead of their own:
     .status-active 3.28:1 on /dashboard, .status-pass 3.22:1 on /audit-logs. Cause:
     ".panel-heading span" (specificity 0,1,1) beats ".status-active" (0,1,0)
     (styles.css:70 and admin-experience.css:308).

Fix
- src/AdminWeb/scripts/generate-dark-theme.mjs derives src/theme-dark.css from the three light
  stylesheets (every rule scoped to :root[data-theme="dark"]); `npm run build` fails if the
  generated file is stale (--check). Sidebar, brand and command palette are already dark and
  are left alone.
- src/AdminWeb/src/theme.tsx: System / Light / Dark selector in the top bar, stored in this
  browser only (localStorage "taskmonitoring-admin-theme"); System follows the OS setting.
- public/theme-init.js sets the theme before first paint (same-origin script, allowed by the
  production CSP script-src 'self').
- kbd colour #c3ccda; ".panel-heading span:not(.status-badge)" in both stylesheets.
