G-34 / G-35: one shared realtime connection per Admin Web tab, client library loaded on demand
Date: 2026-10-14
Branch: perf/admin-web-shared-realtime, base main after #79

Status: G-34 OPPORTUNITY (now implemented), G-35 initial-bundle target reached

Change:
  New src/AdminWeb/src/realtime.ts: one HubConnection per tab, created on the first subscription and
  stopped when the last subscriber leaves (deferred by a microtask so a page change keeps it).
  @microsoft/signalr is imported dynamically. PresencePanel, OperationsIncidentRealtimeNotice,
  SecurityAlertRealtimeNotice and WebsiteWorkRealtimeNotice subscribe to their events through it.
  A connection opened for one signed-in user is never reused for another (the token subject is checked).
  The server side is unchanged: RealtimeHub.OnConnectedAsync puts the connection in groups by
  permission, so one connection receives the same events the four separate ones did.

Real-stack check (scripts/audit/realtime-shared-connection.mjs):
  Local API from main, scratch PostgreSQL DB tm_rt_check (dropped afterwards), Jwt__AccessTokenMinutes=1,
  Vite dev server, Playwright + Chromium. The script signs in as the bootstrap audit admin, moves
  through four pages with the sidebar, lets a fictional employee start and submit a website-work target,
  waits 80 s so the access token expires (the server closes the hub, G-22), then submits a second one.
